## dxls workbook naming

The format is named **dxls**, with default extension **`.dxls`**. Native save dialogs and extension completion use `.dxls`; case-insensitive input is accepted. Legacy `.duxcel` files remain readable and can be saved under the new suffix using Save As. Version 4 adds independently anchored pivot/chart definitions and placement; version 3 introduced manual cells and per-sheet canvas zoom. Future document icons, type registration and packaging must consistently use lowercase dxls.

Application identity uses the approved blue/green modular grid duck, preserving the white segmented duck and yellow bill; the rejected yellow monogram is excluded. The upper symbol is reconstructed as the canonical SVG, with generated immediate C geometry, 23 prebuilt PNG sizes, ICNS, ICO and hicolor/SVG packaging inputs. There is no per-frame file reading, SVG parsing or heap allocation. Settings uses one startup mipmapped texture for antialiased small curves. Native AppKit decodes every registered ICNS representation, and the running bundle's About panel displays the approved symbol and Duxcel name. Eight icon/gallery/Settings stages pass at 100/125/150/200% icon scales on light/dark and 100/150% UI on the host Retina 2x display. Windows/Linux assets have structural checks only. The generator reproduces all 56 derivatives byte-for-byte on the current toolchain; details are in [assets/icons/README.md](assets/icons/README.md).

## Technical debt and constraints

- LIMIT/OFFSET can repeat scans/sorts; deep CSV offsets remain expensive. Do not assume arbitrary relations have stable row keys.
- Source page memory is capped at 16 MiB and object pages at 4 MiB; wide/long results fail recoverably. Projection and a long-value inspector would improve usability beyond rejecting oversized pages. Clipboard projection is implemented.
- First source window now publishes before exact count; a cancellable background count updates the lower-bound row status. Count publication is deferred during thumb dragging, and growth conflicts retain the last good result. Core tests pass; the 12-stage native count/recovery smoke now passes after unlock.
- The canvas has one primary source/analysis and a fixed source-header band, plus independently anchored pivots, charts and manual ranges. Independent table sources are implemented; primary table placement and imported-value overlays remain.
- Undo/redo is session-only; changing/saving source references does not snapshot external data. No inherent relational row order or deterministic sort tie policy is promised.
- Catalog metadata is cached for an attachment; live external schema changes require refresh/reopen semantics.
- DuckDB conversion helpers are deprecated; vector/chunk extraction remains future work. Views with original-catalog references may fail under an attachment alias.
- Interface scale/DPI changes rebuild font atlases; canvas zoom reuses the atlas. Startup/font cost, missing glyph coverage, IME input and complex-script shaping need further work.
- Workspace version 6 adds independent table sources and bindings while retaining readers for versions 1–5, placement/overlap validation and bounded definitions. Further transform models need versioned migrations.
- Allocation exhaustion remains fatal; ordinary query/source/workspace errors are recoverable.
- Source cell edits require explicit materialization/overlays; never overwrite external CSV/Parquet implicitly. Worksheet column Undo/Redo restores both values/object placement and column widths.

## NULL semantics and presentation

- SQL NULL is missing data and must be visually distinct from the VARCHAR values `NULL`, `null`, `""`, and an actual zero-length string. Never infer NULL by comparing displayed text. Never substitute a `(blank)` category. Keep genuine source empty strings as strings; do not silently rewrite imported data. Unused virtual worksheet cells remain unallocated canvas.
- Use a quiet, non-interactive monospace type mark for real NULL in source/pivot cells, pivot column categories, filter values, the value strip and chart labels. Empty VARCHAR uses a distinct quoted text mark. Literal text uses normal worksheet typography. Carry typed category components through the worker instead of parsing DuckDB-generated column names.
- CSV imports preserve quoted empty VARCHAR separately from unquoted missing fields (`allow_quoted_nulls=false`); literal `NULL` is text. Check the same distinctions after Parquet conversion.
- Include NULL explicitly in bounded DuckDB PIVOT ON domains so missing categories survive; aliases must not collide with literal `NULL` or with case/delimiter-containing categories. Verify totals, multi-field categories, date domains, empty results, filtered choices and save/reopen in the application.
- Follow up on out-of-range numeric comparison values: casting a filter value into a narrow imported DECIMAL/INTEGER can reject otherwise meaningful predicates. Exact threshold normalization now handles signed/unsigned integers through 128 bits and DECIMAL through 38 digits without floating-point conversion or narrowing the threshold. FLOAT comparisons promote to DOUBLE. Invalid numeric input fails clearly; text/date/boolean retain native typing. Source schema metadata is cached and invalidated when the file changes.
