## Workbook design direction

The user accepted the following future behavior on 21 October 2026. Detailed contracts and implementation parameters belong in the [workbook TRD](design/WORKBOOK_MODEL_TRD.md#19-decision-register); these decisions do not claim implementation or schedule roadmap batches.

- Separate read-only external Connect, workbook-owned Import and materializing a selected query into an optional nonvisual Data Model. Edit internal workbook state; Save writes `.dxls`, while explicit CSV/Parquet export writes data without formatting/history and never implicitly modifies the source.
- Keep DuckDB as the transaction/journal and analytical engine without adding SQLite now. A local journal protects committed edits; explicit Save publishes complete mode-dependent data and required analytical output with progress. Pending/group-commit durability remains a measured contract.
- Save complete pivot/aggregate output and chart data/presentation, including offscreen values. Large connected browse results need not be embedded. Saved Data Model inputs enable offline drill-through into a new query-backed sheet; a saved external-backed pivot alone does not retain its underlying rows.
- Positional A1 references follow analytical object movement. Floating/aligned matrices also expose their own local grid, with preferred `sheet_code.object_code.A1` references and separate code/display names. Snapped-to-floating mode change converts existing analytical sheet references to qualified object-local form in one undoable operation. Focusing a matrix projects its local headers into the existing chrome. Semantic GETPIVOTDATA-style lookup is a deferred nice-to-have, not a prerequisite.
- Grid analytical objects cannot overlap each other on the same sheet; floating objects may overlap visually with reachable controls. Blocked placement retains the last successful mapping and computed values for inspection while bound reads report spill errors. Master View starts inspection-first with explicit ownership and independent sheet geometry; it never merges their address spaces.
- Show an on-object warning when known data/query/definition changes postdate the displayed complete analytical result. Save may preserve the newer definition and previous complete result with their distinct provenance/status. Recalculate dependent formulas after new output arrives; invalid references, values or calculations produce typed errors in their formula cells, while valid changed values recalculate normally.
- Successful Refresh replaces affected data and resets its ad hoc row/cell formatting and local value overrides. Retain compatible column formats and conditional rules; rules reevaluate new values. Do not prove record survival/deletion, diff old/new rows, reconcile duplicates or suspend styles for automatic reattachment. Failure/cancellation preserves current state; normal bounded Undo/version retention remains. Save/tag before Refresh to retain a durable prior state. This does not clear unrelated worksheet content or remove existing same-version sort/filter format coverage.
- Retain cross-session Undo across the latest three version states including Latest Saved, plus the current suffix: V8→V9 and V9→V10 in the ten-state example. Preserve older tagged checkpoints independently. Workbook visualization defaults stay outside data Undo; Automatic formats look up the current default and explicit formats remain fixed.
- Historical Save As captures the inspected state with optional selected history. Preserve recoverable current work on version restore. Keep bounded alignment with no automatic sheet resizing, safe initial rejection of occupied manual destinations, and one analysis placement initially. Correct oversized close/unsaved dialogs using the existing native UI's proportions.
