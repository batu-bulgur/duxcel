# Repository and delivery audit — 17 October 2026

The native engine and existing module boundaries are worth preserving. The project needs a reproducible development loop and clearer acceptance boundaries more than another architectural redesign. This review used three independent read-only audits of source structure, test execution and design/status claims, followed by isolated implementation branches.

## Scope and file handling

The inventory walks **all local project files outside Git administration**, classifies dependencies/builds/data/evidence separately, and hashes every versionable project file. [FILES.tsv](FILES.tsv) lists the owned files and intentional derivatives; `tools/project_inventory.py` reproduces it. The ignored `build/project-audit/full-inventory.tsv` includes dependency/generated file metadata. Inventory and classification are exhaustive; this does not claim a semantic review of every third-party dependency, pixel or generated binary. Authored native modules, tests, build/tools, design requirements and asset provenance were inspected by responsibility and by concrete feature claims.

Before cleanup, most disk usage was local material: roughly 456 MiB downloaded public data, 423 MiB generated fixtures, over 178 MiB results, and 101 MiB prototype dependencies. These are related project resources, not evidence that they should all be deleted. Sizes are logical-file totals at the initial scan; results may grow during tests.

## Course correction

1. **Use one definition and one current status.** The rendered prototype is the exact visible/interaction target. Explicit product requirements define behavior beyond its mock engine. Keep those two scopes clear.
2. **Accept UI parity separately from advanced analysis.** Some prototype Marks targets only update tokens. Finishing arbitrary query-grain/continuous scales is valuable future product work, but should not make the visible port expand indefinitely. Real native controls still need working supported actions or honest disabled states.
3. **Finish small correctness debts before more polish.** Active-origin selection, retained readout, focus modality, moved-table bookmarks and source-format identity deserve bounded scenarios and clear completion evidence.
4. **Replace full-suite-per-edit with tiers.** The implemented warm grid/choiceview gate takes 0.452s for 46,228 release/sanitizer assertions. The full 17-module gate passed 74,820 assertions in 39.734s, including 29.468s rebuilding. The older full native pass is about 14 minutes. Use affected checks during iteration and the comprehensive suite at integration boundaries. Native completion should end a test rather than render idle frames to its timeout.
5. **Parallelize by ownership.** Separate branches/worktrees prevent file/fixture collisions. UI geometry, engine/workbook and tooling can progress independently; one integrator owns App/shared changes and one desktop owner runs native tests. Start with two active build/engine lanes on this 8 GB Mac.
6. **Measure workflow improvement.** Record cold versus warm compilation, test execution, scenario/stage count and source/binary hashes. Preserve assertions and sanitizer coverage. Later incremental objects/generated dependencies and safe icon coordination should remove broad rebuilds; simply removing `.NOTPARALLEL` would introduce races.

This approach preserves the existing computing engine and the user's exact design, while giving each remaining feature a reviewable scope and an appropriate verification cost.

## Implemented during the audit

The plan was exercised with three isolated implementation branches/worktrees: test tiers, the optional-error fix, and completed-native-test termination. Reviewed commits were integrated into main without conflicting file ownership. Fast/affected runs, a warning-free release build and the native runtime comparisons passed; [the evidence index](../validation/README.md) records their exact scope. The matched export regression uses 45% less elapsed time by ending after completion. The existing full 988-stage result belongs to the earlier frozen binary; no new full pass is claimed.

Temporary managed worktrees were archived after their useful ignored evidence was copied back. Git retains the branches/commits and recoverable snapshots. Future work can use the same model, with two build/engine lanes and a single App/desktop integration lane. Incremental compilation and harness extraction remain separate planned changes.
