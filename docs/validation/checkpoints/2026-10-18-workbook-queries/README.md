## Contract and limits

`queries` is required for writer versions 12, 13 and 14. The continuation follows a complete object-descriptor registry. Owner 0 means the sheet's primary definition; a nonzero owner must identify a Table on that same sheet. Pivot/Chart source links are not aliases for Table query ownership. Full unsigned 64 IDs stay exact text until parsed in C, including IDs above 2^53 and `UINT64_MAX`.

The original named schema is checked before the canonical C projection. The C-built query orders `(sheet_id, object_id)` and limits one execution to 2,113 rows: at most 64 primary owners plus 2,048 Tables, followed by an overflow sentinel. A complete 2,112-row result is fed to the C reader as eight 256-row batches plus 64, without SQL OFFSET paging or broadening the ordinary 256-row transport. The dedicated `workbook-owners` policy admits at most 2,113 rows and exactly three columns, with offset 0, no known-total claim and one captured archive registration. The existing DXP1 decoder is reused.

The trusted CASE projection converts SQL NULL, over 64 KiB query text, native `trim`-empty text and embedded NUL into a required NULL atom before wire encoding. This preserves every valid query byte, including quotes, Unicode, trailing spaces and a newline. Pure atom validation remains a separate boundary; it does not substitute C whitespace rules for DuckDB's SQL `trim` semantics. Literal `NULL` is valid query text and differs from SQL NULL and empty text.

Each accepted batch deep-copies its strings. A failed batch preserves the accepted prefix, active cursor and owned byte count; completed Headers remain independently owned. Getters return borrowed const text and preserve the caller's output on failure. Complete Header getters do not turn a stored Table query into a fabricated complete `Analysis`.

The component tests cover ownership, source-owner/type/order errors, malformed text, exact IDs, bounded admission and retry. The actual Worker flow additionally poisons already-transferred owned Page strings before freeing them, rejects the two physical final-row whitespace/NUL packages at accepted prefix 2,048, and holds a real completed callback through stale supersession. Its six generated feed failures preserve prefixes `[0,0,0,0,2048,0]`; one original-schema rejection occurs before canonical casting. All nine terminal proof flags are observed true.

The Worker test driver uses 2 MiB Header admission and 4 MiB input coexistence; the separate native comparison uses 8 MiB logical reader/input admission. Page-wire text/wire limits remain 4 MiB/6 MiB. These are explicit logical ownership/admission categories, not engine/JavaScript/allocator/RSS peak measurements. Native archived queries and source paths are retained metadata; no saved source SQL runs.
