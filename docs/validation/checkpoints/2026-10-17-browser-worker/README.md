# Official Worker behind the shared C99 UI — 17 October 2026

The real browser backend now accepts source pages, counts, SQL validation, historical previews and source-table objects. C builds the SQL, describes the original SQL schema, projects canonical VARCHAR text in DuckDB, and decodes bounded DXP1 pages into its own allocator. JavaScript handles official Worker/platform transport. Native production gains no browser runtime.

The official npm package is pinned to **1.32.0**; the running embedded engine reports **v1.4.3**. The accepted artifact uses its official single-threaded **EH** bundle. `official-eh-probe.json` verifies exact BIGINT/UBIGINT/DECIMAL, nanosecond timestamp and canonical HUGEINT text, SQL NULL/empty/literal NULL, paging/transfer, useful errors and latest-wins/cancellation. Direct Arrow HUGEINT is explicitly unsupported; the actual C backend uses engine-produced canonical VARCHAR with original SQL metadata. The earlier MVP probe is retained as rejected bundle evidence: its missing-table error reported `_setThrew is not defined`; EH returns the real Catalog Error and recovers.

`c-worker/` is the integrated no-window C/real-Worker acceptance: **13 complete stages**, **1,907 checks** in this run, **22 submitted SQL requests** and one count. It verifies 12 original typed columns, exact strings and owned Pages, all 600 rows across 256/256/88 pages, schema reuse, table/preview/validation requests, a real missing-column error, recovery, active long-query supersession/cancellation, cookie/ticket rejection and callbacks after shutdown. Checks include frame-dependent polling assertions, so the total can vary; all 13 stages and semantic assertions must complete. The browser counters describe C submissions, which may be superseded before engine execution. The whole no-build gate took **6.094 s**, including 5.901 s in the browser phase. It creates a separate acceptance artifact and exports no controls into the shipping UI.

`public-parquet/` loads the existing **59,158,238-byte** public NYC Parquet through the browser file chooser into the actual C App, Worker and grid. It verifies **3,475,226 rows /20 columns**, while the UI owns a **256-row** page. Selection to C page/count publication took **1.690 s** in this sample. The preserved wide/narrow captures show actual source cells and Fields. `csv-sort/` verifies the five-row/six-column fixture, real descending source sort and the unprefixed source label. Its import publication took **568 ms** and the complete no-build UI gate took **7.177 s**. These are local end-to-end observations, not engine-only or input-latency benchmarks.

The first Parquet gate took 44.430 s overall: browser 9.160 s, local-server reverse DNS 35.018 s. The harness now binds explicit loopback metadata without reverse DNS; the next CSV gate measured server setup 0.001 s. Older W1 wrapper timings measured the browser phase after server setup, not total wall time. The wrapper now records setup and total elapsed separately. Tests use the shared desktop lock, an ephemeral loopback server and a unique owned headless Chromium profile. No window activates or switches a user Space. Timed-out runners terminate only their own process group.

`pure.json` and `pure.txt` record **907 wire +220 SQL +58 workbook-model checks per release/ASan+UBSan configuration**, **37 Node transport/host/probe tests** and six packaging fixtures. The warm gate took **1.270 s**. Controlled host tests cover import/read/init/admin races, query supersession, close during registration, heap relocation, OOM cleanup and source extensions. The actual Worker/C driver is separate from these test doubles.

Fresh native release/sanitizer session drivers each pass **26 checks** (1.420/1.588 s), plus the **477-check** hidden-window probe (1.275 s). `native-lifecycle/` records exact native binary/source scope. `shipping-absence.json` verifies no added browser/review symbols in rebuilt native shipping binaries, no review/test signatures in the normal UI Wasm, and no acceptance-host/probe assets packaged with that UI. This does not repeat the full native inventory or close visual parity.

`application-build.json` records the exact normal browser artifact: UI Wasm 2,905,251 bytes; all packaged assets 40,357,255 bytes before compression. It includes fonts/icons, the official EH engine and ESM dependencies, but excludes C/JS acceptance drivers and the Worker probe. Reusing C objects relinked/packaged in 2.079 s. Source/binary/component hashes and flags belong to their individual recorded runs; no newer unrelated source is covered by an older pass.

Still open: browser PIVOT/domain/totals, available-value/date dropdown queries, statistics/copy/export and workbook save/relink; total registered-source budget and streaming file handles; browser review exports, DPR/Retina, clipboard/IME/context loss and other browser/platform acceptance. Imports are capped at 256 MiB per file and registered sources remain until session teardown. Native analytical features retain their earlier independent acceptance.
