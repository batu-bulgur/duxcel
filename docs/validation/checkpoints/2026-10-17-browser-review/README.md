# Shared C browser reporting — 17 October 2026

W4 now uses the same C registry, actual pre-overlay frame capture, picker, note composer and worker-publication fence as native review. `make web-review` produces an isolated Wasm target. Browser glue intercepts its shortcut before GLFW, freezes CSS/backing geometry, copies owned C JSON/RGBA buffers and prepares one `.dxreview.tar` download. It adds no DOM widget tree or alternate spreadsheet UI. Native thread/outbox storage stays native; browser download preparation is explicitly not durable outbox/OPFS storage.

Three real hidden Chromium runs accept **DPR 1, DPR 2 and DPR 2 with an inset/scaled canvas**. Each imports actual CSV data, opens the City filter, requests capture, picks `filter.search`, enters the UTF-8 note `İ filter`, downloads an archive and returns to the unchanged open filter. Reporting submits no database jobs. The existing project-scoped reader retrieves the C target, source location, image and frame/build identity from the exported manifest/PNG. Captures were visually inspected: the exported frame has the original popup and no picker/composer decoration. Actual archive members and PNG dimensions/hashes are checked, not just a transport helper.

Whole gates take **12.516 /11.111 /12.994 s**. Export snapshots contain a 1280×820 RGBA image (**4,198,400 bytes per owned pixel buffer**), roughly 35 KiB C metadata and roughly 160 KiB PNG. Measured synchronous buffer copies take **0.7–1.0 ms**; PNG/hash preparation takes **28.6–33.1 ms**, before archive construction/download. These are local export observations, not input-latency, peak-RSS or engine-time measurements. Browser C capture retains its own frozen image/texture until reporting closes; the asynchronous host owns independent copies.

At DPR 2, the current raylib browser target still has a **1280×820 backing buffer for 1280×820 logical/CSS pixels**. The sidecar records DPR 2 separately from the actual 1× framebuffer ratio; it never substitutes DPR for the transform. Retina sharpness remains open. The inset case records CSS scales **0.8/0.8** and offsets **102.390625/49.1875** while retaining the C framebuffer and logical dimensions; real pointer picking still resolves the correct textbox. All runs also render the resized narrow window, though the browser export itself is captured at 100% UI scale in the wide state. Wider reporting-state/150%-scale/browser acceptance remains separate.

The archive contains the exact portable C `manifest.json` (`duxcel.native-review` v1, retained for reader compatibility), `frame.png` and `browser.json`. Browser metadata binds report/session/frame IDs, actual Wasm SHA-256, frozen CSS/backing/DPR/visual viewport transforms, file byte counts and SHA-256 values. Browser sessions use cryptographic random IDs. Export completion is asynchronous and cookie/ticket fenced; cancellation/disposal invalidates work before C image/JSON release. A disposed host is rejected on later C creation; a new App/module needs a fresh host. Failure retains the note/pixels for retry.

**13 pure Node groups** cover ownership, actual PNG decoding/CRC in fixtures, independent USTAR checksum/padding parsing, frozen metadata, exact UTF-8, hash binding, errors/retry, supersession/cancel/dispose, URL cleanup and shortcut order. GLFW installs a window capture listener, so the review listener is registered first and only intercepts a focused canvas chord. **17 runner checks** pass; runtime/HTML/dependency metadata in `web/` now participates in source fingerprints, while generated dependency directories are pruned. Build publication rechecks every source/host/asset input hash.

Native review passes **26 stages per optimized/sanitizer configuration**, plus the 477-check hidden-window probe: 2.283/2.492 s and 1.937 s respectively, with a 1.920 s warm build. This validates the shared capture/composer guards and native durable reader workflow after the browser seam. The rebuilt normal browser App also passes actual CSV import/sort/narrow interaction in **7.514 s**.

`shipping-absence.json` examines actual compiled Wasm exports, source/flag/link inventories, loader/assets and forbidden binary markers. The review artifact positively contains its C capture callback/modules; normal Wasm and both rebuilt native shipping binaries exclude the added review/browser bridge as applicable. All artifacts are immutable/versioned. The desktop lock, private headless profiles and hidden native windows preserve user focus/Spaces.
